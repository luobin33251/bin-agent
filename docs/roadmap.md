# 开发路线图

## 里程碑总览

| 阶段 | 内容 | 验证标准 | 状态 |
|------|------|----------|------|
| **M0** | 项目骨架 + SQLite 数据层 + Agent 循环 + SSE 服务 | 对话能流式返回 | ✅ 已完成 |
| **M1** | 录入闭环：检索与写入工具 + 卡片回显确认 | 说一段话能被正确归类入库，卡片可纠正 | ✅ 已完成 |
| **M2** | 检索闭环：FTS5 + 向量混合检索 + 问答调取 | 问「我上次记的空调那事」能调出来 | ✅ 已完成 |
| **M3** | 文件接入：`scan_folder` / `read_source_file`（PDF/Excel/OCR） | 本地资料目录里的存量文件可被语义搜到，文件原地不动 | ⏸ 暂停（用户指定先做 M4/M5） |
| **M4** | 保险箱：主密码 + 加密存储 + 前端解锁查看 | 密码不参与索引和日志，回复中只显示掩码 | ✅ 已完成 |
| **M5** | 手机端：PWA + 内网访问 | 手机能录入和查询 | ✅ 已完成（轻量版，不含 service worker） |

阶段划分的逻辑：**M1 + M2 是核心闭环**（写入 + 读取），跑通后任何新信息类型
都只是往里灌数据。M3–M5 是能力扩展。

## M1 完成情况（已交付）

### 已定的两个设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 写入工具粒度 | 三个工具：`search_memory` / `save_memory` / `correct_memory` | 把「建类别」和「写条目」合进 `save_memory`，"先查后写"就成了服务端不可绕过的逻辑，模型没法偷懒 |

```
   search_memory → save_memory → card(采购跟进/新建) → save_memory → card(待办事项/新建)
   ✓ 一句话自动拆成「采购记录 + 催开票待办」两条

② 再记一条：8月3日给另一家供应商买了2台打印机，花了3839.22，已经开票报销了
   ✓ 复用「采购跟进」，typeIsNew=false，字段结构完全一致

③ 帮我找一下上次记的空调那事
   ✓ 命中并输出结构化回答

④ 刚才空调那条金额记错了，是 63000，发票已经开了
   correct_memory → card(corrected)
   ✓ 生成 diff：金额 62995→63000、发票状态 未开→已开、摘要同步更新
```

落库数据核对：

| 检查项 | 结果 |
|---|---|
| 类型自演化 | 2 个类型由 AI 创建，`usage_count` 分别为 2 / 1 |
| 枚举一致性 | `发票状态: enum ["未开","已开","已报销"]`，两条记录取值均在枚举内 |
| 原话留存 | `entries` 原样保存，只增不改 |
| 索引同步 | `search_index` 与条目一一对应 |
| 日期换算 | 「月底」→ `2026-10-31`，「8月3日」→ `2026-08-03` |

### 开发中发现并修掉的问题

| 问题 | 现象 | 处理 |
|---|---|---|
| 模型不知道当前日期 | 「8月3日」被记成 **2025**-08-03 | 系统提示词每次请求现算并注入当天日期 |
| 中间过程与结论拼接 | 正文变成「我先查一下…找到了…改好了…」读不通 | 前端在 `tool_call` 时把已有文字移入 `preamble`，与最终结论分开渲染 |
| 新建类型 `usage_count` 为 0 | 刚用过的类型被「孤儿类型」逻辑误判 | 新建后立即计一次使用 |
| enum 的 `options` 被丢弃 | 同类记录同一字段各写各的（已开/已开票/已开票报销），**无法聚合统计** | 参数 schema 与 `toFieldDef` 补上 `options` |
| 摘要与字段脱节 | 金额改了，摘要里还写着旧值 | 提示词要求改字段时回头同步摘要 |

### 试用期暴露的问题（已修）

| 问题 | 现象 | 根因与处理 |
|---|---|---|
| **模型误判库是空的** | 用户问「记了哪些事」，模型答「系统里什么都没有记下来」并向用户道歉——**数据其实好好在库里** | `search_memory` 在 `scope=types` 时返回 `totalItems: 0`（因为没查条目），模型把「本次没查」读成了「一条都没有」。改为 `librarySummary`（库里总量）与 `matchedTypes/matchedItems`（本次命中）分离，未查询的范围返回 `null` 而不是 0 |
| **模型叙述没做过的动作** | 「我做了个小清理」「我来合并清理」，然后什么都没发生 | 提示词新增「只能描述真正做过的事」硬性约束；同时把「系统没有删除/合并功能」明确写进能力边界，让它直接说做不到 |
| **同一件事被记两遍** | 「王工PDA采购（6台）」和「10月7日发起6台PDA采购」字段、日期完全一致 | 模型查重不可靠。`save_memory` 落库前加服务端查重：**同类别 + 相同发生时间 + ≥2 个字段值一致**即判定疑似重复，返回 `ok:false` 并列出已有记录，模型据此询问用户。用户确认是两笔独立记录时，可带 `confirm_duplicate=true` 重调 |

> 查重规则刻意保守（要求字段值完全一致），因为只看标题相似度抓不到这类重复——
> 上面两条的标题差异很大。保守的代价是可能误拦真实的两笔相同采购，
> 所以设计成「拦截 + 询问」而不是「静默丢弃」。

### 试用期的能力补全：删除 / 合并 / 恢复

发现重复记录后，模型只能口头说「我来合并清理」——因为没有对应工具。
补上三个（迁移 `002_item_soft_delete` 同时加入 `items.deleted_at`）：

| 工具 | 说明 |
|---|---|
| `merge_memory` | 保留 target，source 的字段只补 target 的空缺后被软删除。两条重复记录往往各有一半信息，删哪条都丢东西，合并才是对的做法 |
| `delete_memory` | **软删除**，只有用户明确要求时才可调用 |
| `restore_memory` | 恢复已删除。有这个工具，软删除才算真正成立——否则删了回不来，软删除就只是"看不见的硬删除" |

实测合并两条重复记录：存活条目 3 → 2，被并入的那条 `deleted_at` 非空但数据完整保留，
`search_index` 同步摘除，`entries` 里连被删记录的字段快照都留了档。

### 已知残留风险

**模型偶发「假称已保存」**：实测出现过一次模型回复「记好了」但根本没调用 `save_memory`。
已在提示词里加了硬性约束，但这属于模型的固有不确定性，提示词只能降低概率、无法根除。

缓解手段是产品层面的：**卡片就是收据**。用户看到「记好了」却没有卡片，就能立刻察觉。
M2 之后可以考虑加一条兜底——当回复声称已记录但本轮没产生卡片时，前端显式警告。

## M2 完成情况（已交付）

### 已定的几个设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 嵌入服务 | 百炼专属端点，`qwen3.7-text-embedding`（1024 维） | 中文效果好、便宜、OpenAI 兼容；且**不回落**到对话模型配置——两者厂商与端点不同，回落会拿只能跑对话的套餐 key 去打嵌入接口 |
| 向量生成时机 | **写入时同步算**，失败不影响落库 | 刚记完就能被语义检索到；API 挂了只是暂时只能靠关键词找到它 |
| 漏算怎么补 | **启动自检 + `pnpm reindex`** | 算向量是异步 HTTP，必定会有失败；靠自检自愈，而不是要求每次调用都成功 |
| 融合方式 | RRF（k=60），FTS 那路 `ORDER BY rank` | 两路分数量纲不同，加权平均要归一化、只能靠试；RRF 只看名次，免调参 |
| 相似度下限 | **0.4**（实测量出来的） | 相关 0.68~0.83、同语境无关 0.30~0.41，所以 0.2 等于没设下限 |
| 得分要不要给模型 | **给**（`similarity` + `topSimilarity`） | 0.42 和 0.82 都过线但含义差远了，阈值分不出来；实测这一条挡住了「硬答」 |
| 类别要不要向量 | **不做**，仍按名称匹配 | 类别数量少、命名由模型统一生成，语义那路帮助有限 |
| 检索接口形态 | 升级 `search_memory`，不新增工具 | 模型不用学新工具，M1 的「先查后写」链路原样保留 |

### 验证结果

**① 真实数据的检索质量**（库里 3 条真实记录，全部用「换个说法」提问）：

| 提问 | 关键词那路 | 语义得分 | 结果 |
|---|---|---|---|
| 那台服务器的登录信息 | 全空 | 0.742 | ✅ 命中对应的服务器记录 |
| 那批 PDA 的采购什么时候交货 | 全空 | 0.680 | ✅ 命中「10月7日发起 6 台 PDA 采购」 |
| 客户那个接口的进度 | 全空 | 0.829 | ✅ 命中「对接接口开发测试」 |

关键词一路全部落空、语义一路全部命中且排第一——这三个问题在 M1 时代一个都答不出来。

**② 无关提问不硬答**（库里没有空调记录）：

```
问：上次说的那个空调的事，你还记得吗？
答：翻了翻记录，没找到关于空调的内容。目前库里最接近的结果是 PDA 采购那条
    （相似度 0.43），跟空调没直接关系。……要不你多给点线索，我再试试？
```

0.43 过了下限，只靠阈值它会被当成「找到了一条」；模型是看了分数才判断出
「跟空调没直接关系」的。这条同时验证了「得分交给模型」这个决策。

**③ 自愈链路**：配好 Key 后服务重启，启动自检自动补算了 3 条存量条目的向量，
`pnpm reindex` 再跑时缺向量已经是 0 条——不需要人工干预。

**④ 相似度分布实测**（用于定阈值）：

| 类别 | 分数区间 |
|---|---|
| 真正相关（换说法提问） | 0.68 ~ 0.83 |
| 同语境但无关 | 0.30 ~ 0.41 |

### 待观察

- **阈值只有 3 条数据支撑。** 0.4 是把「0.41 的噪声挡掉、0.68 的命中留下」这个
  区间卡出来的，样本太小。等多记几十条真实信息后要重新看分布。
- **模糊提问会被挡掉。** 「和钱有关的记录」这类提问最高分 0.355，现在返回空。
  这是精度的代价——宁可让用户换个说法，也不给一个看起来像真的错答案。
- 批量上限（Provider 默认 10 条一批）在现有数据量下没被压到，M3 接入大量文件时要复验。
- 首次全量回填的限流表现，同样要等数据量上来才知道。

## M4 完成情况（已交付）

### 已定的决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 解密放在哪端 | **服务端** | 前端解密要用 WebCrypto，而它只在安全上下文（HTTPS / localhost）存在——手机走局域网 HTTP 时根本不可用。服务端解密则不依赖 HTTPS，明文只存在于内存与一次响应里 |
| 主密码作用 | 既当加密密钥的来源，又当访问通行证 | 一个口令管两件事，不用记两个；服务端内存持有解锁后的密钥，30 分钟无操作自动锁定 |
| KDF | `node:crypto` 的 scrypt（N=2^15, r=8） | 文档原本写 Argon2id，但那要引原生依赖，不想再踩 better-sqlite3 那种编译坑；scrypt 零依赖、强度够 |
| 每条的密文结构 | **账号 + 密码一起加密成一条密文** | GCM 的 iv 绝不能复用；两个字段各加密一次就得各配一套 iv，而表里只有一套 iv/auth_tag 列 |
| 模型能不能读保险箱 | **完全不能** | 不给任何工具，提示词里明说读不到。这样「不进日志」是结构性保证，而不是靠提示词祈祷 |
| 对话里说了密码 | 照常记录 + 提醒风险 | 用户的决定。代价是明文会进 `entries`、发给云端模型、进检索索引——所以提醒里要说清 |

| 删除 | 硬删除、列表与库都清空 |

### 明确的代价

- **主密码忘了就解不开**，没有找回入口——这是加密本身的代价，设置页已写明
- **服务端进程能拿到明文**（它跑在你自己的电脑上）。真要对外暴露公网，还得配 HTTPS
- 对话里输入的密码按用户决定照常明文记录，进 `entries`（只增不改）并会发送给模型服务

## M5 完成情况（轻量版已交付）

### 交付物

| 项 | 内容 |
|---|---|
| 单端口托管 | `@fastify/static` 托管 `apps/web/dist` + SPA 兜底；手机只记 `http://<内网IP>:3100` 一个地址 |
| 接口隔离 | 非 `/api` 的未知路径回 `index.html`（刷新不 404）；`/api/*` 的未知路径回 JSON 404，不吐 HTML |
| PWA 壳 | `manifest.webmanifest` + 192/512 图标 + `apple-touch-icon`，可「添加到主屏幕」全屏运行 |
| 手机适配 | `100dvh`（地址栏收起不再压住输入框）、`interactive-widget=resizes-content`、安全区内边距、触摸目标加大、手机端提示改为「点右侧按钮发送」 |
| 剪贴板兜底 | 非安全上下文下 `navigator.clipboard` 不存在，退回 `execCommand('copy')`——否则最需要复制密码的手机端反而复制不了 |

### 验证结果

独立端口跑完 14 项断言，全部通过：静态产物/图标/打包 JS 都能取到、深层路径回首页、
打错的接口回 JSON 404、健康检查与保险箱接口在同源下正常。

### 刻意没做

**service worker**。它同样要求安全上下文（HTTPS），
在当前「局域网 HTTP 直连」的形态下注册不了。等以后接上 Tailscale（能拿到 `.ts.net` 的 HTTPS）
或 Cloudflare Tunnel，再补离线壳与安装提示也不迟。
